# 4.90 → 5.00 (verified against 4.90.8 and 5.00.0 source)

nopCommerce 5.00 moves to **.NET 10** (LTS, supported to November 2028). .NET 8 and .NET 9 — and so nopCommerce 4.70, 4.80 and 4.90 — lose Microsoft support on **10 November 2026**, which is why most stores will make this hop.

## Build

| Item | 4.90 | 5.00 |
|---|---|---|
| `<TargetFramework>` | net9.0 | **net10.0** |
| SDK | .NET 9 | **.NET 10** (`global.json` pins `10.0.401`, `rollForward: latestFeature`) — an IDE that supports .NET 10 |
| `plugin.json` `SupportedVersions` | `["4.90"]` | **`["5.00"]`** |
| `.csproj` | `$(SolutionDir)` layout | unchanged apart from the target framework |
| Solution | `src/NopCommerce.sln` | unchanged |

Update NuGet packages your plugin references to versions built for .NET 10 (e.g. `Microsoft.*` 10.0.x). If the plugin referenced packages core used to carry (AutoMapper, FluentValidation.AspNetCore), see below.

## Libraries replaced

### AutoMapper → Mapster

Core dropped AutoMapper and uses **Mapster** behind the same `ToModel<T>()` / `ToEntity<T>()` extension methods. Mapping profiles change:

```diff
-using AutoMapper;
 using Nop.Core.Infrastructure.Mapper;

-public class MapperConfiguration : Profile, IOrderedMapperProfile
+public class MapperConfiguration : BaseMapperProfile
 {
     public MapperConfiguration()
     {
         CreateMap<MyEntity, MyModel>()
             .ForMember(model => model.SomeProperty, options => options.Ignore());
         CreateMap<MyModel, MyEntity>();
     }
-
-    public int Order => 1;
 }
```

- `BaseMapperProfile` (in `Nop.Core.Infrastructure.Mapper`) supplies `CreateMap<TSource, TDestination>()`, `ForAllMaps(...)`, `Order` and a virtual `Init()`.
- `ForMember(member, options => options.Ignore())` and `options.MapFrom(...)` are provided as nop extension methods over Mapster, so most profiles compile with only the base-class change.
- AutoMapper-only features (`ConvertUsing`, `AfterMap`, `ResolveUsing`, value resolvers, `ReverseMap`, `IMapper` injection) have no shim: rewrite them with Mapster's `TypeAdapterConfig` API or map by hand.
- `AutoMapperConfiguration` was removed; core's mapper is `Nop.Core.Infrastructure.Mapper.MapperConfiguration`.

### FluentValidation 11 → 12

- `FluentValidation.AspNetCore` is gone. Core references `FluentValidation` and `FluentValidation.DependencyInjectionExtensions` 12.x and does automatic validation itself: `BaseController` carries `[AutoValidation]` (`Nop.Web.Framework.Mvc.Filters`), and client-side rules come from `Nop.Web.Framework.ClientsideFluentValidation`.
- Validators deriving from `BaseNopValidator<TModel>` keep working. Remove any `using FluentValidation.AspNetCore;` and any package reference to it.
- `IsCreditCard()` (nop's `CreditCardPropertyValidator`) was removed: use FluentValidation's built-in `.CreditCard()`.
- Check validators for APIs removed in FluentValidation 12 (for example the old `CascadeMode.StopOnFirstFailure` value) against the FluentValidation 12 upgrade guide.

## Forums, News and Polls moved out of core into plugins

Core no longer contains forums, news or polls. They are now the plugins **`Nop.Plugin.Misc.Forums`**, **`Nop.Plugin.Misc.News`** and **`Nop.Plugin.Misc.Polls`**, each with its own domain, services, settings, permissions and views (for example `Nop.Plugin.Misc.News.Domain.NewsItem`, `Nop.Plugin.Misc.News.Services.NewsService`, `Nop.Plugin.Misc.News.NewsSettings`).

Removed from core:

| Removed | Notes |
|---|---|
| `Nop.Core.Domain.Forums.*`, `Nop.Core.Domain.News.*`, `Nop.Core.Domain.Polls.*` | except `PrivateMessage`, which moved to **`Nop.Core.Domain.Customers`** (`ICustomerService` gained `Get/Insert/Update/DeletePrivateMessage…Async`) |
| `IForumService`, `INewsService`, `IPollService` and their caching consumers | use the plugin's services — which means your plugin now depends on that plugin being installed |
| `ICustomerService.IsForumModeratorAsync` | removed |
| `IMessageTokenProvider.AddForumTokensAsync`, `AddForumPostTokensAsync`, `AddForumTopicTokensAsync`, `AddNewsCommentTokensAsync` | removed |
| `IWorkflowMessageService.SendNewForumTopicMessageAsync`, `SendNewForumPostMessageAsync`, `SendNewsCommentStoreOwnerNotificationMessageAsync` | removed from core (`SendPrivateMessageNotificationAsync` and `AddPrivateMessageTokensAsync` stay) |
| `PublicWidgetZones.Boards*`, `NewsItemPage*`, `NewsListPage*`, `HomepageBeforeNews`, `HomepageBeforePoll`, `CustomerForumSubscriptions*` | removed — widgets that render in those zones stop showing |
| `AdminWidgetZones.Forum*`, `News*`, `Poll*` | removed |
| `BBCodeHelper` / `IBBCodeHelper`, `ResolveLinksHelper`, `NopBBCodeEditorTagHelper`, `Nop.Services.Html.CodeFormatter.*` | removed (forum formatting) |
| Public views `Views/Boards/*`, `Views/News/*`, `Shared/Components/HomepageNews`, `HomepagePolls`, `PollBlock`, `NewsRssHeaderLink`, `Profile/Components/ProfilePosts` | now in the plugins; theme overrides of them must move to the plugin's view paths |

If a store used forums, news or polls, **install the matching plugin** as part of the upgrade and check on a staging copy that the existing posts, news items and polls are there before going live.

## Namespaces moved

| Type | 4.90 | 5.00 |
|---|---|---|
| `IWebHelper`, `WebHelper` | `Nop.Core` | **`Nop.Services.Helpers`** |
| `IThemeContext` | `Nop.Web.Framework.Themes` | **`Nop.Services.Themes`** |
| `PrivateMessage` | `Nop.Core.Domain.Forums` | **`Nop.Core.Domain.Customers`** |

`IWebHelper` is used by most plugins: add `using Nop.Services.Helpers;` (and drop `using Nop.Core;` if nothing else needs it).

## Synchronous service methods removed

Only the async versions remain:

| Interface | Removed sync methods | Use |
|---|---|---|
| `ILocalizationService` | `AddOrUpdateLocaleResource`, `DeleteLocaleResources`, `DeleteLocaleStringResource`, `UpdateLocaleStringResource` | the `…Async` methods; in **migrations** use `this.AddOrUpdateLocaleResource(dict)` / `this.DeleteLocaleResources(names)` (below) |
| `ISettingService` | `InsertSetting`, `UpdateSetting`, `DeleteSetting`, `ClearCache` | `…Async`; in migrations `this.SetSettingIfNotExists(...)`, `this.GetSettingByKey<T>(...)`, `this.DeleteSettings(predicate)` |
| `ILogger` | `Error`, `Information`, `Warning`, `InsertLog` | `ErrorAsync`, `InformationAsync`, `WarningAsync`, `InsertLogAsync` |
| `IStoreService` | `UpdateStore` | `UpdateStoreAsync` |

## Migrations

`MigrationExtension` became **`MigrationExtensions`** (same namespace `Nop.Web.Framework.Extensions`) and no longer needs services passed in:

```diff
 public override void Up()
 {
-    var (languageId, languages) = this.GetLanguageData();
-    var localizationService = EngineContext.Current.Resolve<ILocalizationService>();
-    localizationService.AddOrUpdateLocaleResource(new Dictionary<string, string>
-    {
-        ["Plugins.Misc.MyPlugin.NewField"] = "New field",
-    }, languageId);
+    this.AddOrUpdateLocaleResource(new Dictionary<string, string>
+    {
+        ["Plugins.Misc.MyPlugin.NewField"] = "New field",
+    });
 }
```

`GetLanguageData()` was removed; `RenameLocales(dict)` no longer takes the language list and service. New helpers: `DeleteLocaleResources`, `DeleteSettings(predicate)`, `DeleteSettingsByNames(names)`, `GetSettingByKey<T>`, `SetSettingIfNotExists`.

## Other signature changes (compile errors you may hit)

| 4.90 | 5.00 |
|---|---|
| `IPriceFormatter.FormatBasePriceAsync(product, productPrice, totalWeight)` | `FormatBasePriceAsync(product, decimal? basePrice)`; compute the base price with the new `IProductService.GetBaseProductPriceAsync(product, productPrice, totalWeight)` |
| `IMessageTokenProvider.AddReturnRequestTokensAsync(tokens, returnRequest, orderItem, languageId)` | gains `Order order` before `orderItem` |
| `IMessageTokenProvider.GetListOfAllowedTokensAsync(IList<string> tokenGroups)` | `GetListOfAllowedTokensAsync(MessageTemplate messageTemplate = null, IList<string> tokenGroups = null)` — a positional token-group argument now binds to `messageTemplate`: **name it** |
| `IWorkflowMessageService.SendContactUsMessageAsync(languageId, email, name, subject, body)` | gains `IDictionary<string, string> customAttributes` |
| `ISearchTermService.GetSearchTermByKeywordAsync` | removed (search terms are per customer now: `SearchTermHistoryItemsAsync`, `DeleteSearchTermsByKeywordAsync`) |
| `UrlHelperExtensions.RouteUrl<TEntity>()`, `RouteTopicUrl()` (`Nop.Web.Framework.Mvc.Routing`) | removed — use `INopUrlHelper.RouteGenericUrlAsync<TEntity>(...)` / `RouteTopicUrlAsync(...)` |
| `NopMetadataProvider`, `IModelAttribute`, `InvariantNumberModelBinder(Provider)` | removed |
| `RoxyFileman` (admin file manager) | replaced by **elFinder** (`elfinder-npm`) |

Implementers only: `IGeoLookupService` gained `LookupCountryIsoCodeAsync` / `LookupCountryNameAsync`; `IProductService` gained 3D-object methods; `IShoppingCartService` gained `SetShoppingCartVendorAsync`.

Unchanged: `IPlugin`, `BasePlugin`, `IWidgetPlugin`, `IPermissionService`, `[CheckPermission]`, `IPermissionConfigManager`, admin menu events, `INopUrlHelper.RouteUrl`, `BaseNopValidator`.

New in core: price lists (`PriceList`), SMS providers (`Nop.Plugin.Sms.Twilio`), phone-number login, reminders, AI recommendations, and new plugins `Misc.PunchOut`, `Feed.ChatGptShopping`, `AIRecommendation.GoogleAI`, `Widgets.Jotform`.

## Views and front end

- Public views for boards, news and polls left `Nop.Web` (see above). New public views appear under `Checkout`, `Common`, `Customer`, `Product`, `ReturnRequest` and `Shared` — re-merge overridden views.
- Front-end packages: **Swiper 11 → 14** (major: check any theme code that configures sliders), driver.js 1.3 → 1.8, jsrender 1.0 → 1.2, Font Awesome 7.0 → 7.3, `marked` removed, `elfinder-npm` added.
