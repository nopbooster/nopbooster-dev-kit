# 4.80 → 4.90 (verified against 4.80.9 and 4.90.8 source)

## Build

| Item | 4.80 | 4.90 |
|---|---|---|
| `<TargetFramework>` | net9.0 | net9.0 (unchanged) |
| VS | 17.12+ | **17.14+** |
| `plugin.json` `SupportedVersions` | `["4.80"]` | **`["4.90"]`** |
| `.csproj` | `$(SolutionDir)` layout | unchanged (core only renamed `logo.jpg` → `logo.png`) |

If the plugin still uses the 4.70 relative `..\..\` paths, apply the `.csproj` change from `470-to-480.md` now.

## Plugin base

- `IPlugin` gained `Task InstallSampleDataAsync()`. `BasePlugin` implements it (no-op), so plugins deriving from `BasePlugin` need nothing; classes implementing `IPlugin` directly must add it.
- `INopUrlHelper.RouteUrl(routeName, values, protocol, host, fragment)` is new — core plugins replaced `IUrlHelperFactory` + `IActionContextAccessor` with it in `GetConfigurationPageUrl()`:

```diff
-        return _urlHelperFactory.GetUrlHelper(_actionContextAccessor.ActionContext).RouteUrl(Defaults.ConfigurationRouteName);
+        return _nopUrlHelper.RouteUrl(Defaults.ConfigurationRouteName);
```

Optional but recommended (`IActionContextAccessor` is deprecated in newer ASP.NET Core releases).

## Views

- **Public:** `Shared/Components/TopMenu` → `MainMenu`; footer links via `FooterMenu`. 176 public view files changed in total (Shared 50, Product 22, Customer 18, Boards 18, Catalog 16, Checkout 10, …). Plugins that override core public views must re-merge them.
- **Admin:** Font Awesome 6.6 → 7.0 — check icon classes in plugin admin views.
- jQuery 3.7 / jquery-migrate / jQuery UI 1.13 unchanged. Prefer `.on("click", …)` and `$(fn)` over deprecated shorthand in plugin scripts, as core views do.
